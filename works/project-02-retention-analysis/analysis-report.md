# Project 02｜D7 留存異常分析正式報告

## 1. 問題定義

本案例模擬一款休閒手遊出現「D1 留存正常，但 D7 留存比上月下降 11%」的情境。  
分析目標不是只描述留存變差，而是回答下面三個問題：

1. 哪一群玩家先流失？
2. 流失前常出現哪些負向事件？
3. 最值得優先驗證的產品調整方向是什麼？

## 2. 分析資料

### 使用資料

- `mock-data/player_events.csv`
  新玩家 install、day_number、session_count、關卡進度、事件類型、payer segment 與留存標記
- `sql/cohort_queries.sql`
  把 cohort 與留存問題翻成可查詢的 SQL 練習
- `outputs/retention_summary.json`
  Python 腳本輸出的結構化結果
- `outputs/chart-*.svg`
  Python 自動生成的 cohort / segment / churn event 圖表

### 分析限制

- 這是一份作品集用假資料，樣本數小，主要目的是展示分析流程與結論組織方式
- 結論應視為「優先驗證假設」，而不是已在商業環境中完全證實的因果判定

## 3. 分析方法

### Step 1｜先看 cohort 留存

先依 install_date 切 cohort，檢查 D1 / D3 / D7 留存變化，確認異常主要發生在前期玩家旅程的哪一段。

### Step 2｜檢查關卡與事件訊號

觀察 reached_level_8、event_type 與 retained_d7 的關係，判斷是否存在明顯卡關點或流失前共通事件。

### Step 3｜切玩家分群

以 payer segment 為初步切法，區分 non_payer、light_payer、mid_payer，判斷異常是否集中在某一類新玩家。

### Step 4｜整理成可執行提案

把數據觀察轉成產品與營運團隊可以驗證的動作，而不是只停在「留存變差」的描述。

## 4. 核心 KPI 摘要

| 指標 | 結果 | 解讀 |
| --- | --- | --- |
| 玩家數 | 12 | 假資料樣本，用來展示分析流程 |
| D1 留存 | 100.0% | 首日沒有明顯異常 |
| D3 留存 | 58.3% | Day 2 到 Day 3 開始出現流失 |
| D7 留存 | 33.3% | 中後段留存明顯不足 |
| 到達第 8 關後流失玩家 | 33.3% | 關卡卡點值得優先檢查 |
| 活動參與玩家 D7 留存 | 50.0% | 有中期目標感的玩家保留較好 |
| 忽略活動玩家 D7 留存 | 0.0% | 中期誘因不足可能放大流失 |

## 5. 主要發現

### 發現 A｜流失高峰出現在 Day 2 之後

D1 留存正常，但 D3 明顯掉下來，代表問題比較不像安裝品質或教學第一分鐘，而更像 Day 2 後的中期體驗斷點。

### 發現 B｜Level 8 是最明顯的卡點訊號

到達 Level 8 並流失的玩家占全部樣本 33.3%。  
這表示第 8 關的難度曲線、補強提示或資源給法，可能是造成挫折放大的主要位置。

### 發現 C｜活動參與與 D7 留存有明顯差異

有參與活動的玩家 D7 留存為 50%，忽略活動的玩家 D7 留存為 0%。  
雖然樣本數不大，但足以支持一個合理假設：第二天後若缺少短期目標，玩家更容易直接流失。

### 發現 D｜non-payer 是最需要再細分的高風險族群

non-payer 量體最大，同時 D7 留存最低。  
下一步若進入真實商業分析，應再拆成高活躍 non-payer 與低活躍 non-payer，確認問題是否集中在低活躍新手。

## 6. 圖表閱讀重點

### Cohort Retention

- 用來確認掉點主要出現在 D3 到 D7，而不是 D1
- 代表前期導入不是完全失敗，但中期目標感不足

### Segment D7 Retention

- 用來比較 payer segment 間的保留差異
- 可以支持「高價值玩家保留較穩定，低付費 / 非付費玩家更容易流失」的判讀

### Top Churn Events

- `level_fail` 出現最多，代表關卡挫折是高優先風險
- `event_ignore` 也偏高，代表中期任務或活動的吸引力可能不夠

## 7. 建議行動

### 優先動作 1｜調整 Level 8 難度與補強提示

- 降低第 8 關失敗密度
- 在失敗後提供推薦卡組、提示或一次性補強資源
- 驗證指標：Level 8 通關率、D3 留存

### 優先動作 2｜補 Day 2 後的短期目標

- 延長新手活動或加一個 Day 2 之後的過渡任務
- 用活動入口、任務獎勵或每日導流強化玩家目標感
- 驗證指標：活動參與率、D7 留存

### 優先動作 3｜對低活躍 non-payer 做召回測試

- 針對低 session_count 且未參與活動的新玩家設計召回訊息
- 驗證是否能把 Day 3 之後的流失率拉回來
- 驗證指標：回流率、D7 retained users

## 8. 驗證規劃

如果這是真實專案，下一輪我會用以下方式驗證：

1. 對 Level 8 難度調整做 A/B test
2. 對 Day 2 後活動入口文案與獎勵做版本比較
3. 針對低活躍新手設計召回訊息並追蹤 D3 / D7 留存差異
