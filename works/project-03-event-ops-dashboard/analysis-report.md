# Project 03｜新春祈福大作戰正式分析報告

## 1. 報告目的

這份案例模擬一檔節慶 Live Ops 活動上線後，營運與分析團隊如何快速回答三個核心問題：

1. 活動是否真的提升參與與回流？
2. 任務節奏與經濟平衡是否健康？
3. 這檔活動是帶來短期營收，還是同時創造可延續的玩家參與？

## 2. 分析資料

### 使用檔案

- `event-brief.md`
  活動定位、目標與核心玩法
- `economy-table.csv`
  活動幣產出、消耗與兌換門檻
- `mock-data/daily_event_kpis.csv`
  活動七天的 KPI 假資料
- `outputs/liveops_summary.json`
  Python 模擬腳本輸出的結構化結果
- `outputs/liveops-analysis-pandas.xlsx`
  pandas 版工作簿輸出
- `outputs/chart-*.png`
  pandas + matplotlib 產出的活動 KPI 圖表

### 使用情境

這份案例不是要模擬超大型商業資料集，而是展示我如何把活動設計與營運數據連成完整判讀流程。

## 3. 問題拆解

### 問題 A｜活動參與率夠不夠高？

如果主入口、任務或獎勵吸引力不足，活動參與率會偏低，代表活動沒有真正啟動玩家循環。

### 問題 B｜中段節奏有沒有掉速？

活動常見問題不是 Day 1 沒人玩，而是 Day 3 到 Day 5 熱度掉下來，導致後續回流與消費力不足。

### 問題 C｜營收成長是否健康？

如果活動只靠禮包刺激付費，但參與率與完成率不穩，長期看就不是健康的 Live Ops。

## 4. KPI 摘要

| 指標 | 結果 | 解讀 |
| --- | --- | --- |
| 活動天數 | 7 天 | 一檔典型短週期節慶活動 |
| 平均 DAU | 13,594.3 | 活動期間整體活躍穩定 |
| 平均參與率 | 60.5% | 已達到活動入口有效啟動的區間 |
| 平均回流玩家 | 1,895.7 | 活動有成功拉回部分沉默玩家 |
| 平均任務完成率 | 73.0% | 基本健康，但中段仍有掉速跡象 |
| 活動總營收 | NT$1,125,400 | 活動有明顯商業貢獻 |
| 平均 ARPPU | NT$348.4 | 付費結構仍屬中價位健康區間 |

## 5. 主要發現

### 發現 A｜活動確實有把玩家帶進來

平均參與率 60.5%，代表主入口、活動主題與每日任務設計具備足夠吸引力，這檔活動不是只有少數重度玩家在玩。

### 發現 B｜Day 4 是最值得檢查的中段掉點

最低任務完成率落在 2026-02-04，只有 68%。  
這通常代表活動在中段的節奏感、提醒強度或任務門檻出現疲勞訊號。

### 發現 C｜活動尾段對營收有明顯拉升

最高營收日是 2026-02-07，顯示保底提醒、收尾刺激或限時壓力在尾段有帶來有效轉換。

### 發現 D｜經濟平衡目前偏可控，但仍需持續監控

免費產出 / 單次抽取消耗比為 2.5，代表玩家有穩定參與就能累積活動幣，但若未來提高產出，可能造成活動價值過鬆。

## 6. 圖表解讀

### Daily Participation & Return

- 用來看活動期間參與與回流是否同步成長
- 如果參與升高但回流不動，代表活動可能只在吃原有高活躍玩家

### Mission Completion Trend

- 用來抓活動中段疲勞點
- 如果 Day 4 明顯掉速，就要回頭檢查任務門檻與提醒節奏

### Revenue & ARPPU

- 用來確認營收成長是否來自健康轉換，而不是過度壓榨高價值玩家

## 7. 建議動作

### 優先動作 1｜優化 Day 4 中段推進節奏

- 下修中段任務摩擦
- 增加 Day 4 的提醒或小型加碼獎勵
- 驗證指標：Day 4 任務完成率、次日參與率

### 優先動作 2｜保留尾段保底提醒機制

- 尾段對營收有正向影響，建議保留保底與結束倒數提醒
- 驗證指標：Day 6 / Day 7 營收、活動幣消耗率

### 優先動作 3｜持續監控免費產出與兌換壓力

- 若未來要提高參與率，不建議直接無上限增加免費活動幣
- 應先從任務設計與入口包裝調整，再看是否需要微調產出

## 8. 驗證規劃

如果這是一檔真實上線活動，我下一步會做：

1. 比較 Day 4 任務調整前後的完成率
2. 比較有無保底提醒版本的尾段營收差異
3. 觀察回流玩家在活動結束後 7 天是否仍維持較高留存

這個作品的目的，是證明我不只會做活動題材與玩法概念，也能把活動拆成：

- 中段節奏觀察
- 回流與營收判讀
- 可驗證的營運提案

這正是遊戲數據分析與 Live Ops 工作會需要的核心能力。
