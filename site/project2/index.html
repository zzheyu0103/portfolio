Problem

先排除流量結構變化，再聚焦新玩家 cohort 在 Day 3 到 Day 7 的斷點。

Working Hypothesis

第 8 關卡關與第二天後目標感不足同時發生

結果不是單一功能出問題，而是難度曲線與中期目標空窗一起放大流失。

SQL Practice

會怎麼查這個問題

Query 
SELECT
  install_date,
  COUNT(DISTINCT player_id) AS installs,
  SUM(CASE WHEN retained_d7 = 'yes' THEN 1 ELSE 0 END) AS retained_d7_users
FROM player_events
GROUP BY install_date
ORDER BY install_date;

接著再往下切關卡事件、活動參與與 payer / activity segment，確認異常是不是集中在某些 cohort。

Insights

最後不是只報告異常，而是給出可以被驗證的改善方向

這三塊剛好能對應你面試時最需要說清楚的能力：觀察、推論、落地提案。

Observation

第 8 關把 Day 2 的玩家卡住了

失敗人次在 Level 8 明顯抬升，且未通關玩家在之後 24 小時內的登入率快速下滑。

Hypothesis

第二天之後的短期目標不夠明確

活動參與率較低的 cohort，D3 到 D7 留存落差更大，代表中期誘因不足。

Action

先做難度修正，再補第二天後的導流任務

優先調整 Level 8 難度與提示，再新增 Day 2 任務獎勵與召回訊息驗證改善幅度。
