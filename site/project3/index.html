Event Name

新春祈福大作戰

以每日任務、祈福幣、福袋與保底兌換組成短期回流與活動參與主循環。

Primary Goal

提升回流、參與與活動期付費轉換

活動不是只衝營收，而是要在不破壞經濟前提下，拉起回流與參與。

Deliverable

活動設計文件 + 經濟表 + 時程 + KPI 面板

這樣的組合更像真正能跟營運、PM 與數據團隊討論的提案格式。

活動參與率 61%

主入口與每日任務是最核心的啟動點，參與率要先拉到六成以上。

回流玩家 +18%

活動應優先吸引沉默玩家回來，不只服務原本高活躍用戶。

禮包轉換率 4.8%

付費轉換不是唯一目標，但能反映獎勵節奏與價值包裝是否合理。

任務完成率 72%

如果每日任務掉太快，就要回頭檢查門檻、流程與提醒節奏。

Design Focus

專案重點

本專案聚焦活動設計、獎勵平衡、營運指標與成效判讀，補足 Live Ops 相關能力展示。

Retention

活動入口要替回流玩家降低重返門檻

每日任務與保底兌換讓玩家即使不衝榜，也有清楚而穩定的參與理由。

Economy

獎勵不能只堆量，還要避免通膨

活動幣產出、消耗與兌換門檻要先算清楚，避免短期刺激換來長期經濟失衡。

Measurement

上線後要能快速判斷活動到底值不值得延長

用參與率、回流率、任務完成率與 ARPPU 做同頁判讀，才有辦法快速做營運決策。

Data Ops Layer
